目標

知道每個 thread 怎麼用 blockIdx、blockDim、threadIdx 算出自己負責的那一格，以及 grid 要開多大才不會漏掉資料。

概念

啟動 kernel 時，GPU 會開出一個 grid（網格），裡面有 gridDim.x 個 block（區塊）， 每個 block 裡有 blockDim.x 個 thread（執行緒）。每個 thread 跑的是同一份程式碼， 唯一的差別是它們拿到的編號不同。

threadIdx.x 只是「我在自己 block 裡的第幾個」，不同 block 之間會重複。 要知道「我在整個 grid 裡是第幾個」，就要把前面所有 block 的 thread 數加上去：

i = blockIdx.x × blockDim.x + threadIdx.x

開出來的 thread 總數是 gridDim.x × blockDim.x。它通常不會剛好等於資料長度 N， 所以會把 block 數取上限：gridDim.x = ⌈N / blockDim.x⌉，多出來的 thread 用 if (i < N) 擋掉。

互動區

把滑鼠移到 thread 或陣列格子上看詳細資訊

Kernel 程式碼

__global__ void addOne(float* a, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;  // 全域索引
    if (i < N) {                                    // 邊界檢查：多開的 thread 什麼都不做
        a[i] += 1.0f;
    }
}

// host 端：block 數取上限，確保 N 個元素都有人處理
int threads = 256;
int blocks  = (N + threads - 1) / threads;   // = ceil(N / threads)
addOne<<<blocks, threads>>>(d_a, N);

常見誤區

  • 只用 threadIdx.x 當索引：每個 block 都會從 0 開始，結果所有 block 都在改前 blockDim.x 格，後面的資料沒人碰。
  • block 數用 N / threads（整數除法）：會無條件捨去，最後不滿一個 block 的那幾筆資料被漏掉。要用 (N + threads - 1) / threads。
  • 忘了 if (i < N)：取上限後一定會多開 thread，它們會讀寫陣列範圍外的記憶體，可能讓程式當掉或悄悄寫壞別的資料。

實務上 blockDim.x 通常選 32 的倍數（例如 128、256），因為 GPU 以 32 個 thread（一個 warp）為單位排程。這會在 Lab 03 看到。

自我檢查

blockDim.x = 8、N = 30，需要幾個 block？會有幾個 thread 被 if 擋掉？
⌈30 / 8⌉ = 4 個 block，共 32 個 thread，其中 i = 30、31 這 2 個被擋掉。可以在互動區設定 N = 30、blockDim = 8 後按「自動算 gridDim」驗證。
blockIdx.x = 2、threadIdx.x = 5、blockDim.x = 16，這個 thread 負責哪一格？
i = 2 × 16 + 5 = 37。
把 gridDim.x 調得比需要的少，陣列會發生什麼事？
thread 總數小於 N，後面的元素沒有任何 thread 負責（互動區裡會變成橘色），結果就是那幾格沒被計算到，而且程式不會報錯。
